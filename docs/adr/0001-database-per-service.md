# ADR 0001. Отдельная база данных на сервис

## Контекст

В системе четыре приложения: реестр, шлюз, отели и бронирования. Отелям и бронированиям нужны собственные данные, при этом прямое чтение чужой БД нарушает границы микросервисов.

## Решение

`hotel-service` и `booking-service` используют отдельные in-memory базы H2 (`hoteldb`, `bookingdb`). Обмен данными идёт только через REST. Распределённые транзакции не применяются.

## Последствия

- Сервисы можно запускать и тестировать независимо.
- Данные очищаются при перезапуске, поэтому демонстрационные данные создаются инициализаторами.
- Согласованность обеспечивается сагой и компенсациями, а не общей транзакцией.
