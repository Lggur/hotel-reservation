# ADR 0002. Сага бронирования с компенсацией

## Контекст

Создание брони затрагивает две базы: сначала нужно занять номер в `hotel-service`, затем сохранить подтверждение в `booking-service`. Атомарной транзакции между базами нет.

## Решение

Бронь создаётся в статусе `PENDING` и подтверждается вызовом `confirm-availability`. При успехе статус меняется на `CONFIRMED`. При ошибке бронь переходит в `CANCELLED` с причиной. Если номер уже занят, но локальное подтверждение не удалось, вызывается компенсационный `release`.

Подтверждение и освобождение идемпотентны по `bookingId`: повторный вызов не создаёт второй слот и не уменьшает `times_booked` дважды.

## Последствия

- Система остаётся согласованной в конечном счёте.
- Зависшие `PENDING` брони восстанавливаются планировщиком.
- Компенсация может не удаться; тогда номер освобождается при повторной попытке.
